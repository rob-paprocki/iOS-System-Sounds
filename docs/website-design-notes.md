# iOS System Sounds: design handoff

## 1. What this is

This is a static website for a repository that has extracted every audio file from the root filesystem of 106 iOS IPSWs, one per iOS major.minor line from iOS 1.0 in 2007 to iOS 26.6, plus every iPhone launch build. Every sound is de-duplicated across all of those builds by four escalating identity tests, so the corpus knows, for each distinct sound, exactly which iOS releases it shipped in. The site's job is to let a person hear a sound before downloading it, and to make that history readable: when a sound arrived, when it disappeared, and what replaced it.

The site is a retrieval tool, not an exhibit. The largest group of visitors arrives from a search engine with one half-remembered word ("tri-tone", "the old text tone", "iPhone 4 lock sound") and wants the file in under a minute. Everything else the corpus can support, the 20 year timeline, the per-build diffs, the bulk export, is built on top of that and reached after it. There is no marketing page, no hero banner, and no landing state that is not already the working tool.

## 2. The data

Everything is generated by the repository's existing Python tooling. Nothing is fetched at runtime except static files.

**Trees on disk (the originals, byte-identical to what Apple shipped):**

| Path | Contents |
|---|---|
| `Current/` | sounds that still ship in the newest iOS build |
| `Removed/` | sounds that shipped once and no longer do |
| `Spoken Content/` | bulk spoken-word assets (Nike+ workout narration and similar), kept separate so they do not swamp the system sounds. Spoken content that has been removed stays in this tree; its `status` field still says `removed`. |
| `web/audio/` | an AAC (`.m4a`) preview mirror of all three trees, same folder structure, same filenames, `.m4a` extension |
| `web/index.json` | the compact index below |

**`web/index.json` top level:**

```
versions:   [ { os, build, device, model }, ... ]   chronological, oldest first. 106 entries.
categories: [ { name, count }, ... ]                name is the full slash path, see below
counts:     { total, present, removed }
sounds:     [ record, ... ]
```

**One record per sound:**

| Field | Type | Notes |
|---|---|---|
| `id` | string | 12 hex chars, the MD5 prefix of the representative file. Use as the permalink key. |
| `title` | string | Human-readable name, e.g. `SMS Received 3`. |
| `category` | string | A **slash path**, e.g. `UI Sounds/iPhone`, `Haptics/System`, `Spoken Content/Nike+ Workout/JAJP/Male`. Split on `/` and take element 0 for the top-level facet. There are 15 top-level categories and several hundred distinct full paths. |
| `status` | `"present"` or `"removed"` | Present means it is in the newest build. |
| `file` | string | Repo-relative path to the original, e.g. `Current/UI Sounds/iPhone/SMS Received 3.caf`. This is the download target. |
| `preview` | string | Path relative to `web/`, e.g. `audio/Current/UI Sounds/iPhone/SMS Received 3.m4a`. This is the playback target. |
| `format` | string | `caf`, `m4a`, `aiff`, `wav`, `mp3`, `flac`. The format of the **original**, not the preview. |
| `bytes` | integer | Size of the original. |
| `duration` | float or `null` | Seconds. May be null; see hard part 8. |
| `first` | integer | Index into `versions[]` of the earliest build this sound appeared in. |
| `last` | integer | Index into `versions[]` of the latest build it appeared in. |
| `in` | array of integers | Every `versions[]` index it shipped in, ascending. Non-contiguous runs are real and meaningful. |
| `original` | string | Apple's own filename, e.g. `sms-received3.caf`. Searchable. |
| `dir` | string | The directory inside the IPSW filesystem it came from, e.g. `23G83__iPhone18,2/System/Library/Audio/UISounds`. Provenance. |

Scale: roughly 6,000 to 9,000 distinct sounds when the ingest completes (the snapshot on disk today is 5,281 across 28 builds and growing). `index.json` is 2 to 3 MB uncompressed. Category volume is heavily skewed: Spoken Content and Photos Memories together are more than half the corpus, and UI Sounds, the emotional centre of the thing, is under 10 percent. Design against that skew, never against raw counts.

Every record in the index has a working preview. Files that could not be encoded (one zero-length placeholder, and Apple IMA4 ADPCM files that needed a Core Audio fallback) are dropped from the index by the build script, so playback never has to handle a missing preview.

**Three new build artifacts this design requires.** They do not exist yet and must be added to the ingest tooling, not faked in the browser:

1. `web/peaks.bin`: one contiguous binary file, 48 unsigned bytes of amplitude peaks per sound, in the same order as `sounds[]`. Under 500 KB for the whole corpus. Fetched once, cached immutably.
2. `web/shelves.json`: three hand-written lists of `id`s for the zero state (see section 4).
3. `web/zips/`: prebuilt zips per top-level category and one for the full corpus, generated at build time. Each contains a `manifest.json` with title, category, iOS range, format and original IPSW path per file, plus the copyright notice as `NOTICE.txt`.

## 3. Who it is for

1. **Someone who half-remembers a sound.** Highest volume. Arrives from a search engine knowing one word. Needs: type it, hear it, download it, leave.
2. **Designers, video editors and musicians.** Need to skim hundreds of short sounds quickly and take several at once, with the original file, not a re-encode.
3. **Apple-history people and archivists.** Need the timeline, the removals, the re-recordings, and the filesystem provenance.
4. **Developers who want the whole set.** Need one link to a category zip or the full corpus zip, and a documented index format.

## 4. The design

One page. No nav bar, no separate category or version pages. All state lives in the query string (`?q=&cat=&status=&from=&to=&id=`) so any view is linkable and back/forward works.

**At rest, top to bottom:**

- **Header strip, one row tall.** Left: the wordmark. Right: a live mono readout, `8,214 sounds · 6,900 present · 106 builds · iOS 1.0 to 26.6`, which updates as filters narrow it.
- **The search field.** Dominant, full width of the content column, in the top third. Autofocused on load. Rectangular, 2px radius, a 2px rule under it that goes from grey to signal blue on focus. The placeholder cycles through phrases people actually use: `Try: tri-tone`, `Try: the old text tone`, `Try: iPhone 4 lock sound`, `Try: camera shutter`. It freezes the moment you focus or type. On the right edge of the field, a mono count: `1,204 of 8,214`.
- **The release ruler.** A single horizontal strip directly under the search field. 106 tick marks, one per build, spaced by **release order, not calendar date**, so 2007 to 2015 is not crushed against the recent quarterly cadence. Tick height encodes how many sounds are alive at that build. Two drag handles narrow the range. Hovering or focusing a tick shows `iOS 10.0 · 14A403 · iPhone 7`.
- **Facet row.** Top-level category chips with counts, multi-select. A Present / Removed / All toggle. Spoken Content is a chip like the others but is **excluded by default**, with the chip labelled `+ Spoken Content (1,939)` so the exclusion is visible and one click to undo.
- **Active filters** render as removable pills above the list whenever any are set.
- **The list.** Dense rows, 44px default, 32px in the dense toggle. One row per sound, left to right: play button, waveform glyph (fixed 120 × 24px), title with Apple's original filename as a small second line, duration, category tag, lifespan bar, status marker, size, download button, and a checkbox that appears on hover or focus. (Revised 2026-09-13: play leads the row rather than trailing it — it is the thing people came to press — and duration sits beside the title rather than out among the metadata. Play is still its own labelled control, so the glyph stays a scrub track and never doubles as a button.) The list is a real grid with sortable column headers (title, category, first seen, last seen, duration, size); sorting is a first-class equal way to browse, not a fallback.
- **The zero state is not empty.** Before any query, the list shows three hand-written shelves, each rendered as ordinary playable rows: **Start somewhere** (Tri-tone, Marimba, Sosumi, the iPhone 4 lock click, the classic text tone, camera shutter), **New in this build**, and **Recently removed**. These are curated by hand from `shelves.json`. They are never generated from category size, which would fill the page with Photos Memories stems.

**The waveform glyph.** Every row is anchored by a real waveform drawn from `peaks.bin`, not an icon. Fixed width regardless of the sound's real duration, because most of the corpus is under half a second and true-to-length would make 90 percent of rows a single hairline. Present sounds are drawn as a solid green fill; removed sounds are drawn as a rust outline with a dashed baseline. The glyph is the scrub track once a sound is playing. It is **not** the play button and it is **not** a hover trigger; play is its own labelled control.

**The lifespan bar.** A 90px strip in each row, drawn against the same 106-tick scale as the ruler above, with filled marks for every index in `in[]`. A sound that shipped from iOS 1.0 to today reads as a solid bar. A sound that died in iOS 7 reads as a stub. A sound that vanished and came back reads as two blocks with a gap, which is the single most interesting fact this corpus holds and it should be visible without clicking.

**Row detail** opens inline, pushing content down, never navigating away: a larger scrubbable waveform, the full 106-tick filmstrip with build labels, the IPSW path, format, bytes, first and last seen, every variant MD5, and two downloads (original and preview). Sounds whose PCM is identical across every build they appear in carry a marker: `Unchanged since iOS 1.0`. That comes free from the dedup pipeline and it is worth surfacing.

## 5. Interaction

**Searching.** Instant as you type, client side, no submit button and no debounce. Field-weighted ranking: exact title match, then title prefix, then title fuzzy, then Apple's original filename, then category path, then framework directory. Filename weight must stay clearly below title weight, and it must be tuned against real queries ("text tone", "old lock sound", "tri-tone") before launch, not assumed correct. When the match came from something other than the title, the row shows a small note saying so: `matched filename: sms-received3.caf`. Matched substrings get a pale yellow wash. Inline operators (`category:Haptics`, `status:removed`, `before:iOS7`) work and are documented behind a small "search tips" toggle, never in the main chrome.

**Filtering.** Category chips, status toggle and ruler range combine with the query as one AND. Every change is instant and rewrites the URL.

**Playing.** One shared `<audio>` element for the whole page, created and unlocked on the first user gesture. Pressing play on a row stops whatever else is playing, swaps the element's `src` to that row's preview, and sweeps a playhead across that row's glyph. Click anywhere on the glyph to seek. Nothing ever autoplays. There is no hover-to-play, at all: a large part of this corpus is alert and emergency tones, and a mouse passing over a list should not make noise.

**Comparing releases.** A Compare control turns the ruler into a two-handle bracket. Pick two builds and the list becomes a diff of that range: unchanged sounds drop out, additions show a `+` marker and a green glyph, removals show a `−` marker and a rust glyph, and sounds whose title survived but whose audio changed show a split glyph marked `re-recorded`. A summary line reads `+142 added · −38 removed · 3 re-recorded`. This is a filter mode over the same flat list. It is not a second rendering engine, not a canvas timeline, and not a separate page.

**Comparing two sounds.** Check exactly two rows and press Compare in the selection tray to get an inline split view: both waveforms stacked on a shared time axis, independent play buttons, and an A/B button that plays one then the other back to back at matched volume. This is the view a re-recorded pair opens into.

**Selecting and downloading.** Every row has a download button that is a plain `<a download>` pointing at the original file, so the core action works with JavaScript disabled. Checkboxes collect rows into a bottom tray showing count, total size, Compare, Download and Clear. Tray download builds a zip client side with a streaming zip writer, including the same `manifest.json` the prebuilt zips carry. Selections over 200 files show a warning and a link to the relevant prebuilt category zip instead. Category and full-corpus zips are always prebuilt at build time, never assembled in the browser. The copyright line appears in the tray, next to every download button, and inside every zip.

**Keyboard.** `/` focuses search from anywhere. `Escape` clears the query, then blurs. Arrow up and down move a roving focus through rows. `Enter` expands the focused row, a second `Enter` collapses it. `Space` toggles play on the focused row. `X` toggles its checkbox. `D` downloads it. `Shift+Arrow` extends a selection range. The ruler handles take arrow keys to nudge by one build, `Home` and `End` to reset. Every one of these has a visible on-screen control as well; nothing is keyboard-only.

## 6. Visual direction

**Light, on paper.** Three of the four source concepts reached for near-black with one accent colour, which is the default this genre has worn out. This is an index of physical artifacts from a 20 year filesystem, and it should read like a records ledger: ink on paper, hairlines doing the structural work, nothing glowing.

**Palette.**

| Token | Value | Used for |
|---|---|---|
| ground | `#F4F2ED` | page background, a warm index-card grey, not cream and not white |
| surface | `#FBFAF7` | header, row hover, drawer, tray |
| ink | `#16181A` | primary text |
| ink-muted | `#5B6060` | secondary text, filenames, metadata |
| rule | `#D4D0C6` | every hairline, 1px, no shadows |
| present | `#1F6F5C` | solid waveform fill and the filled status dot |
| removed | `#9A4A20` | outline waveform, dashed baseline, hollow status ring |
| signal | `#1F3BB3` | focus rings, selection rail, primary buttons. Never carries data meaning. |
| match | `#FFE58A` | search-match wash only |

The rationale: green ink for a sound still in service, rust for one that has oxidised out of the system. Rust rather than red, because a removed sound is aged, not an error. Blue is reserved entirely for what the user is doing, so a focus ring can never be mistaken for a status.

**Type.** Two families, both open licence, both self-hosted as subset woff2 with `font-display: swap`.

- **Public Sans** for interface text, titles, labels and buttons. It was drawn for government records interfaces. It is plain without being Helvetica and carries no startup accent.
- **Fragment Mono** for data that genuinely is data: build numbers (`14A403`), device identifiers (`iPhone9,3`), durations, byte counts, file paths, the live count readout. Monospace is load-bearing here because those columns align. It is never used decoratively for labels. If its numerals read poorly at 11px, substitute Martian Mono and nothing else changes.

Sizes: 15px row title, 12px mono metadata, 13px body, 11px chips. Sentence case throughout; no tracked-out all-caps eyebrows.

**Density and shape.** Zero border radius everywhere except 2px on inputs and buttons. No cards, no drop shadows, no per-row containers. Hierarchy comes from hairlines, weight and the sans/mono contrast. Rows are separated by a single 1px rule. The drawer and tray are separated from the list by a rule plus a 2 percent ink wash, not a shadow.

**Motion.** Two moments and no others: the playhead sweeping a glyph during playback, and a 120ms height transition when a row expands. The placeholder cross-fade is the only decorative motion and it stops permanently on first focus. Hover and focus are instant state changes. `prefers-reduced-motion` removes the sweep (leaving a filled and unfilled bar), snaps the expansion, and disables the placeholder cycle.

## 7. The hard parts

1. **Thousands of sounds under half a second, which all look and sound alike in a list.** Every row gets a real waveform drawn from `peaks.bin`, at fixed width rather than true-to-duration, so a 0.2 second click and a 90 second stem are equally legible. Amplitude is scaled per sound, not globally, so a quiet tap still shows a shape. Duration is printed as a number next to it, because the glyph deliberately no longer encodes length. Until `peaks.bin` ships, rows render a flat placeholder bar, never a fake generic icon.

2. **A 2 to 3 MB index.** The build emits two files. `index.core.json` carries only what search and the list need (id, title, category, status, format, duration, first, last, original) and is fetched on load. `index.detail.json` carries `file`, `preview`, `in[]`, `dir` and `bytes`, and is fetched at idle right after first paint, not per row. Parsing happens in a Web Worker, which builds the search index and packs the list fields into columnar typed arrays (status, category id, format, duration, first, last as `Int16Array`/`Float32Array`) so filtering, sorting and ruler dragging are index maths over primitives rather than property lookups across 9,000 objects. The list is virtualised: about 40 rows in the DOM regardless of match count. The input is usable within a frame or two, with a small `indexing…` note until the worker reports ready.

3. **Audio element limits on mobile.** Exactly one `<audio>` element exists for the life of the page. It is created and unlocked inside the first user gesture (iOS will not play otherwise), and its `src` is swapped per play. Nothing is preloaded, nothing is prefetched, and no audio request is made until a play button is pressed. A small LRU of recently played URLs relies on the HTTP cache rather than holding decoded buffers.

4. **CAF and AIFF do not play outside Safari, and IMA4 ADPCM plays nowhere.** Playback always uses the AAC preview. Download always gives the original. The two are never confused: the row shows a format badge for the original (`caf`, `aiff`, `wav`), and the download control carries the line `Original file, .caf. Preview above is AAC.` Sounds with no decodable preview are absent from the index entirely, so the player never has to fail gracefully.

5. **98 release lines and 106 builds on a phone-sized screen.** The ruler is ordinal, not calendar, so ticks are evenly spaced and the recent dense years do not swallow 2007 to 2012. On viewports under 640px the ruler collapses into two select menus (From build / To build) plus the same tick strip rendered read-only underneath as context, with 44px touch handles when dragging is available. The per-row lifespan bar survives at every width; it is the mobile answer to "when did this exist".

6. **Making removal and re-recording legible.** Status is triple-coded: colour (green / rust), shape (filled dot / hollow ring), and a text label. The lifespan bar shows gaps, so a sound that was removed and reinstated is visible in the list without opening anything. Re-recording is detected at build time: same title and category, different PCM identity across builds. Those pairs are marked `re-recorded in iOS 7` in the row detail and open directly into the A/B compare view. In diff mode, added, removed and re-recorded carry `+`, `−` and a split glyph respectively, so none of it depends on colour.

7. **The corpus is statistically dominated by the least interesting part of it.** Spoken Content is excluded by default and the chip says so with its count. Category chips are ordered by editorial importance (UI Sounds, Ringtones & Alert Tones, Telephony & Messaging, Camera & Photos, Haptics first), never by size. The zero state is three hand-written shelves. No part of the default view is driven by raw counts.

8. **`duration` is null for most records today.** The ingest must fill it with a single ffprobe pass; it is cheap and the whole duration column, the sort, and the "0.31 s" in every accessible name depend on it. Until then, the UI prints nothing rather than `0.00`, and duration sort is disabled with a tooltip explaining why. Same policy for any field the pipeline has not caught up on: omit it, do not invent it.

## 8. Accessibility

Every control is a real focusable HTML element. The list uses `role="grid"` with rows and gridcells and a roving tabindex, so a screen reader gets the same table structure a sighted user sees, including sortable column headers with `aria-sort`.

Every play button's accessible name states what will play and its duration and status: `Play Tri-tone, UI Sounds, 0.8 seconds, present since iOS 1.0`. A visually hidden `aria-live="polite"` region announces play state changes (`Playing: Tri-tone`, `Stopped`) and filter results (`1,204 of 8,214 sounds`), because a sweeping playhead means nothing to a screen reader. Live region updates are throttled so fast typing does not flood it.

Status is never colour alone: shape plus colour plus a visible text label, in the list, in the row detail, and in diff mode. Contrast is checked at AA against the paper ground for every text and status colour, and the light palette means the whole thing is also legible printed or in grayscale.

No sound ever plays without a deliberate press. There is no hover trigger and no preview-all control. This matters more here than on a typical audio site because the corpus contains emergency and alert tones.

Every download is a plain `<a download>`, so the primary action survives JavaScript being off or failing. The ruler handles take keyboard input and expose `aria-valuetext` as a build name, not a number. Motion is skipped under `prefers-reduced-motion`. Layout is rem-based and reflows to a single column below 640px, and holds at 200 percent zoom.

For someone who cannot hear the sounds: the waveform is drawn for every row whether or not anything is playing, so shape and duration give some sense of a sound unheard, and title, original filename, category, path and version history are enough to find and download the right file confidently. This is a real limit and the design does not pretend otherwise. Most of the corpus is non-verbal, so there is nothing to caption; the two categories that do contain speech (Voice Previews and Spoken Content) have no transcript in the source metadata, and this design does not claim to fix that.

## 9. Scope

**In v1:** the single-page search surface; instant field-weighted search with match disclosure; category, status and release-range facets; the ordinal release ruler with drag-to-filter; virtualised rows with waveform glyphs, lifespan bars, inline play and inline download; sortable column headers; inline row detail with full provenance and the `Unchanged since iOS 1.0` marker; diff-between-two-builds mode; two-sound A/B compare; selection tray with capped client-side zip plus manifest; prebuilt category and full-corpus zips; hand-written zero-state shelves; URL-addressable state; an About panel with the copyright notice, the index format, and the download-all links.

**Explicitly deferred:** client-side spectrograms; waveform rendering beyond the first 30 seconds of long stems; transcripts of any kind; a dark mode; saved or synced favourites; per-variant byte-level diffing; sharding the index by category or era (revisit only if real-world load times prove the two-file split is not enough); any kind of account, comment or rating.

**Dropped from the source concepts, and why:** the multitrack timeline as the primary screen, because it puts the lowest-volume audience in front of the highest-volume one and costs a custom 2D rendering engine to do it; the mixer solo/mute metaphor, for the same reason; PP Neue Machina, because it is a paid licence and the light direction does not want a faceplate face; hover-to-play, because of alert tones, mobile parity and accessibility; the DAW keyboard grammar (`B`, `⌘Enter`, number-key category jumps), because it optimises for one audience at the cost of everyone else, and the same actions are available on labelled controls; the glyph as play button, because it collided preview and commit on one target and pushed download behind a drawer.

## 10. Non-negotiables

1. **The copyright notice.** The audio is Apple Inc.'s copyrighted work. The repository grants no licence to it. This sentence appears in the footer, in the About panel, beside every download control, in the selection tray, and as `NOTICE.txt` inside every zip: *"These sounds are Apple's copyright, collected here for reference, preservation and research. Downloading one does not give you a licence to use it."* It is plain body text at normal contrast, never a muted footnote and never a dismissible banner. Nothing in the copy, the styling or the framing may imply the sounds are free to use.
2. **Download gives the original, never the preview.** The AAC mirror exists only for playback. Every download control points at `file`. The original's format is stated at the point of download. The preview is separately downloadable from the row detail, labelled as a preview.
3. **Static hosting, no server.** GitHub Pages or Cloudflare Pages. No backend, no database, no runtime API. Search, filtering, diffing and ad-hoc zipping all run in the browser. Anything that cannot run in the browser runs in the ingest pipeline at build time.
4. **No autoplay, ever, and no hover-triggered audio.**
5. **Per-row inline download.** The single most common action must never be more than one click from the list, and it must be a plain anchor that works without JavaScript.
6. **The category tree is Apple's own folder structure.** Do not invent, merge or rename categories to make the UI tidier. Do not flatten the slash paths away; the subcategory is real information.
7. **Spoken Content stays separate.** It may be included by the user, but it never appears in a default view.
8. **No Apple pastiche.** No iOS chrome, no SF fonts, no Apple logos or product imagery, no styling that could read as an official Apple property.

## 11. Where this is deployed

Decided 2026-09-12. These are constraints on the build, not suggestions.

**The site source lives in this repository under `site/`.** The audio, the index and the
generator are all here, so the data contract cannot drift between two repositories.

**Revised 2026-09-13: the site is a Cloudflare Worker with static assets, and the audio is in
an R2 bucket the same Worker serves.** The reasoning for keeping audio out of the site host is
unchanged — Pages caps a free-tier site at 20,000 files and 25 MiB per file, and the corpus is
already roughly 10,730 files, close enough to that ceiling that a few more years of iOS
releases would break it. R2 has no egress charge and no file-count ceiling, so audio scales
independently.

What changed is the front: a Worker rather than Pages, and the bucket fronted by that Worker
rather than exposed publicly on its own domain.

- **One origin.** `/audio/*` and `/originals/*` are paths on the site, not a second host. No
  CORS preflight before every play, no separate domain to keep alive, and the Worker answers
  Range requests properly — Safari will not play an `<audio>` source that cannot serve a range.
- **The bucket stays private.** Only the Worker reads it.
- **No build step.** `site/` is uploaded verbatim, so CI only runs `wrangler deploy`.

`preview` and `file` in the index are still resolved against configurable bases, so the audio
origin can move again without touching the index. Those bases now happen to be same-origin.

**The index is committed, the preview mirror is not.** `site/data/` holds the four small files
the page fetches at runtime (3.4 MB), so a clean clone can be served and deployed without
ffmpeg. `web/` stays gitignored.

**The preview mirror is never committed.** `tools/make-web.py` builds it, and it ships as
`iOS-System-Sounds-web-bundle.zip` on the GitHub release, so the site can be built without
ffmpeg. It is pushed to R2 with `tools/upload-audio.sh`, never generated at deploy time — the
Cloudflare build image has no ffmpeg, and with no build step it never needs one.

**Sizes, measured rather than estimated:**

| | |
|---|---|
| Originals, all 5,359 sounds | 355 MB |
| AAC preview mirror, 5,358 sounds | 191 MB |
| `index.core.json` | 1.07 MB |
| `index.detail.json` | 2.09 MB |
| `peaks.bin` | 0.26 MB |
| Whole corpus playing time | 5.1 hours |

**1,982 of the previews are stream copies, not re-encodes.** Every `.m4a` in the collection is
already AAC, and a fraction of the CAF files are too, so those are remuxed rather than
re-encoded and are bit-identical to Apple's audio. The remaining 3,375 are encoded at 96 kbps.
Roughly half the CAF files turn out to be Opus in a CAF container; they are currently
transcoded to AAC for one-format simplicity, but remuxing them to WebM would preserve the
original stream if that trade is ever worth revisiting.
